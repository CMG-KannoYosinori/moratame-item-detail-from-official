# モラタメLPづくりの進行役

ブランドサイトをもとに、モラタメの商品詳細ページ（`tamesu.php?project_id=xxx` の「商品概要」の範囲）を作る。工程は次のとおり。詳しい決まりは [docs/requirements.md](../../../docs/requirements.md) にある。

| 工程 | スキル | 人の確認 |
|---|---|---|
| 0 聞き取り | このスキル | — |
| 1 コンテンツ整理 | `brand-content` | — |
| 2 ワイヤーフレーム | `lp-wireframe` | ✅ ブロックと商品を選ぶ |
| 3 デザインカンプ | `figma-comp` | ✅ 承認 |
| 4・5 HTMLと確認 | `moratame-html` | ✅ 最終確認 |
| 6 修正対応（何回でも） | `lp-revise` | ✅ 修正の確認 |

## 始めるとき

1. [projects/progress.md](../../../projects/progress.md) を読む。
2. ユーザーの依頼が、途中の案件の続きか、新しい案件かを判断する。
   - **続き:** progress.md の「次にやること」から再開する。どこから再開するかを1行で伝えてから進める。
   - **修正:** HTML ができている案件（工程5以降・完了・公開後）に、メーカーからの戻しや「ここを直して」が来たら、工程6（`lp-revise`）に進む。前の工程に戻ってやり直さない。
   - **新しい案件:** 工程0から始める。
   - 判断できないときは、AskUserQuestion で「どの案件か」を聞く（選択肢に progress.md の案件と「新しい案件」を並べる）。

## 工程0: 聞き取り

前回の案件の値を使い回さない。毎回聞く。

**文章で聞くこと**（URLや番号は選択肢にできないので、1通のメッセージにまとめて聞く）:

- **FigmaファイルのURL**（デザインカンプを作るファイル。毎回聞く）
- 案件番号（テンプレートの `00000` を置き換える番号。決まっていなければ練習用の仮番号 `999xx` を、progress.md で使われていない番号から提案する）
- ブランドサイトのURL（複数可）
- 対象商品（モラタメで今回試せる商品）と個数。分からなければ「工程2で選ぶ」でよい
- 分かれば商品情報（内容量、価格など）

**AskUserQuestion で聞くこと:**

- 配送の条件: 通常 / 沖縄以外 / 冷凍便 / 冷蔵便（送料の注意書きを選ぶのに使う）

聞き終えたら:

1. `projects/{案件番号}/wireframe/content.md` を作り、冒頭に「案件情報（工程0）」の表を書く（例: [projects/99901/wireframe/content.md](../../../projects/99901/wireframe/content.md)）。仮の値には「**仮:**」と付ける。
2. projects/progress.md の表に案件を足し、案件の節を作る。

## 工程を進める

各工程は Skill ツールで対応するスキルを呼ぶ。工程が終わるたびに:

- projects/progress.md の表と、案件の節（状態、確認中のこと、次にやること）を更新する。
- 人の確認が必要な工程では、**そこで止まって**、何を見てほしいか・どう返事をすればよいかを伝える。人の返事を待たずに次の工程へ進まない。

人の返事の受け方:

- 工程2: ユーザーが画面で保存したら `blocks.md` を読み、`lp-wireframe` の「保存の後の見直し」をする。「これで進めて」と言われたら工程3へ。
- 工程3: 修正の指示は、会話でも Figma のコメント（`get_comments`）でも受ける。「承認」「OK」などと言われたら工程4へ。
- 工程5: 指摘を直し、「OK」と言われたら完了。progress.md を「完了」にする。
- 工程6: 修正を反映して見せ、「OK」と言われたら changes.md の該当の回を「済」にし、progress.md を更新する。次の修正が来たら、また工程6をする。

## 守ること

- ブランドサイトを基準にする。過去のモラタメのページは形式の参考だけにする。
- 薬機法・景表法に関わる表現は言い換えない。体への働き・効果をうたう表現、対象者と矛盾する訴求（例: 乳幼児は避けるべき商品の子ども向け訴求）は載せる前に人に確認する。
- Amazon や楽天などの購入ボタンは載せない（モラタメの申し込みと競合する）。
- テンプレート（`template/`）の中身は編集しない。
- このフォルダが git で管理されていない（`.git` がない。スタッフに zip で配った場合）ときは、コミットや push の話をしない。git で管理されているときのコミットは、ユーザーが `commit` と言ったときだけ（`.claude/rules/git-commit.md`）。
- 迷ったら、推測で進めずに人に聞く。ただし聞くのは、人にしか決められないことだけにする。
