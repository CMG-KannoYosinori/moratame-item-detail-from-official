# 工程2: ワイヤーフレームとブロックの選択

出力: `projects/{案件番号}/wireframe/wireframe.html` と `blocks.md`
見本: [projects/99901/wireframe/](../../../projects/99901/wireframe/)

## 1. ファイルを用意する

1. [tools/wireframe/template.html](../../../tools/wireframe/template.html) を `wireframe.html` に、[tools/wireframe/blocks.template.md](../../../tools/wireframe/blocks.template.md) を `blocks.md` にコピーする。
2. `{{案件番号}}` `{{商品名}}` `{{ブランドサイトURL}}` `{{配送の条件}}` を置き換え、例のブロックを消して、この案件のブロックに置き換える。
3. 見た目と動き（チェック・並べ替え・メモ・商品の区分・保存）は共通のファイル（`tools/wireframe/wireframe.js`・`wireframe.css`・`frame.css`）が受け持つ。**wireframe.html にインラインの `<script>` を書かない。** どうしても書くときは、文字列やコメントの中の閉じタグを `<\/` と書く（Live Server が最初の `</body>` の前にスクリプトを差し込むため）。

## 2. ブロックを作る

- content.md の内容を、LPのブロック候補として**多めに**並べる。人が選んで減らす前提。
- 各ブロックに ID（`B01`、`B02`…）を振り、ブランドサイトのページ順を基本に並べる。
- 見た目はグレーの箱（`.img`。中にファイル名と大きさを書く）と、**実際の文言**だけ。色や装飾はまだ入れない。
- 種類（requirements.md 3.2節）:
  - **必須**（`tag--req`、最初からチェック）: KV、商品ラインナップ、法令で求められる表示（栄養機能食品の表示など）
  - **おすすめ**（`tag--rec`、最初からチェック）: ブランドサイトの主要な訴求、ブランドサイトへのバナー、X投稿のお願いなど
  - **任意**（`tag--opt`、最初はチェックなし）: あってもよいもの。今回お届けする商品（`-delivering-items`）もここ
  - **自動で入る**（`tag--sys`、ID なし、最後に置く）: 今回タメせる商品（`include_tpl`）、送料関係費のご注意（工程0の配送の条件）
- **動画:** content.md の「動画」に ID（`Y1`…）のある YouTube があれば、`-youtube` のブロックを出す。
  - 1本1ブロック。ただし同じ商品の同じ内容の動画が2本以上あるときは1ブロックにし、ほかを「差し替え候補」として書く。
  - 対象商品の CM と、ブランドサイトのトップに埋め込まれていた動画は「おすすめ」、それ以外は「任意」。
  - 画面には、16:9 のグレーの箱（`<div class="img" style="aspect-ratio:16/9">`）に「YouTube 埋め込み 16:9」、ID、題名を書く。サイトの近くの文言があれば、箱の下に写す。
  - 置く場所は、ブランドサイトで動画があったところに合わせる（トップの KV の下にあれば、リードの近く）。
- blocks.md の各行に、使うテンプレート部品（requirements.md 7節。なければ「案件専用」）と、元にしたページを書く。
- 表現の注意で「載せない」としたものは、ブロックにせず「候補から外したもの」に理由と一緒に書く。

## 3. 商品ラインナップ

- 商品一覧のすべての商品をカード（`.card.prod`、`data-product="P1"`）にし、枠に `class="prods"` を付ける。
- 各カードの商品名の上に `<p class="try">今回試せる商品</p>` を置く（対象のときだけ表示される）。
- 最初の区分（`data-default` と blocks.md の「商品」の表）: 工程0の対象商品を「対象」、関係の近い商品（同じシリーズの別の味など）を「紹介」、包装違いなどを「載せない」にする。対象が分からなければ、いちばん代表的な商品を「対象」にし、仮だと書く。

## 4. 人に選んでもらう

1. `python3 tools/wireframe-server.py`（Windows では `python`）を Bash の `run_in_background` で起動する（ポートが使用中なら別の番号を渡す）。
2. `http://127.0.0.1:8000/projects/{案件番号}/wireframe/wireframe.html` を伝え、次を説明する。
   - チェックで使う/使わない、↑↓で並べ替え、メモで指示、商品カードの右上で区分を選ぶ
   - 終わったら「blocks.md に保存」を押して、会話で知らせてほしい
3. 開く前に、ページが動くことを確かめる（例: `curl` で 200 が返る。可能なら headless Chrome で読み込み、`#status` に「読み込みました」と出ることを見る）。

## 5. 保存の後の見直し

ユーザーが保存したと言ったら `blocks.md` を読み、短く挙げる。

- **抜け漏れ:** 対象商品の個数がどこにも出ていない、対象商品の法令の表示がない、など
- **重複:** 同じ内容を2つのブロックで言っている
- **表現の注意:** 体への働きをうたう表現、出典の注記が外れたブロックにしかない、など
- **動画:** content.md に動画があるのに、動画のブロックがない（または外された）ときは、それでよいかを聞く。タレントが出ている動画は、使ってよいかの確認が要ることも伝える

ユーザーの頼みに合わせて `blocks.md`・`wireframe.html`・`content.md` を直す。新しいブロックは続きの ID（`B18`…）で足す。直したら、ページを再読み込みしてほしいと伝える。

- **`blocks.md` を直す前に、画面で選んだ内容を保存してもらう**（保存していない選択は再読み込みで消える）。
- ページを開いた後に blocks.md が書き換わると、画面の保存は上書きを防ぐために止まる。そのときは再読み込みしてもらう。

「これで進めて」と言われたら、projects/progress.md を更新する（使うブロックの並び、対象・紹介の商品、仮の値）。
