# 修正フロー（HTML を作った後の修正）

HTML を作った後（公開後も含む）に、メーカーからの戻しなどで修正が入ったときの進め方です。修正は何回来てもかまいません。1回の依頼を「第1回」「第2回」…として扱います。

Claude 側の手順は、スキル `lp-revise`（[.claude/skills/lp-revise/SKILL.md](../.claude/skills/lp-revise/SKILL.md)）にあります。

## 全体の流れ

```
修正のファイルが届く
  ↓ ① 置く        revisions/round-N/request/ に入れて、Claude に「第N回の修正です」と伝える
  ↓ ② 一覧にする  Claude が依頼を1件ずつに分け、種類と直すものを表で見せる
  ↓ ③ 残す        Claude が直す前の dist/ を revisions/round-N/before/ に写す
  ↓ ④ 直す        blocks.md・カンプ（Figma）・HTML をそろえて直す
  ↓ ⑤ 確かめる    PC・SP の表示、ルール、表現、before/ との差を見る
  ↓ ⑥ 見せる      直した一覧と画面を見せる → 人が確認して「OK」
  ↓ ⑦ 記録する    changes.md を「済」にし、進み具合を更新する
次の修正が来たら、また ① から（第N+1回）
```

最初の工程（ワイヤーフレーム、カンプ）に戻ってやり直すことはしません。依頼ごとに、影響するところだけを直します。

## 人がすること

1. 届いた修正のファイルを、Finder（Windows ではエクスプローラー）で `projects/{案件番号}/revisions/round-{N}/request/` に入れる（ファイル名はそのまま）。
   - フォルダがなければ、Claude に「第N回の修正のフォルダを作って」と頼む。
   - メールの本文は、会話に貼り付けるだけでもよい（Claude が文章を `request/` に書き残す）。
   - 画像は、会話に貼っただけではファイルとして残らない。残したいものはファイルで入れる。
2. Claude に「第N回の修正です」と伝える。
3. Claude が見せる一覧を見て、聞かれたことに答える。
4. 直したものを確認して、よければ「OK」と伝える。
5. 必要なら「メーカーへの返信用に、修正内容のまとめを作って」と頼む。

## 受け取れるファイルの形式

| 形式 | 受け取れるか | 補足 |
|---|---|---|
| 文章（会話に貼る・メールの本文） | ◎ | いちばん確実 |
| PDF（赤字入りの校正紙など） | ◎ | 1回に読めるのは20ページまで（長いものは分けて読む）。クリックしないと開かない注釈（付箋のコメント）は読み落とすことがある |
| 画像（スクリーンショット、赤字を書き込んだ画像） | ◎ | 手書きの赤字も読めるが、くせのある字は確認することがある |
| Figma のコメント | ◎ | カンプに直接コメントしてもらえば、そのまま拾える |
| Word（.docx） | ◎ | 文字を取り出して読む。変更履歴（足した文字・消した文字）とコメントも読める |
| Excel（.xlsx） | ○ | セルの文字は読める。セルの色や貼った画像は読めない |
| PowerPoint（.pptx） | △ | 文字だけ。図への書き込みは読めないので PDF がおすすめ |
| メールのファイル（.eml）、zip | ○ | 中身を取り出して読む |
| Google ドキュメントなどの URL | × | ログインが必要なページは開けない。PDF などで書き出して渡す |
| パスワード付きのファイル | × | パスワードを外したものを渡す |
| 動画・音声 | × | 文章か、画面のスクリーンショットにする |

迷ったら PDF にしてもらうのが確実です。差し替え用の新しい画像は、ファイルのまま `request/` に入れてください。

## 依頼の種類と、直すもの

| 種類 | 例 | 直すもの | 進め方 |
|---|---|---|---|
| 文言・数値の修正 | 見出しの言い回し、スペック、注意書き | （事実なら content.md）、カンプ、HTML | 続けて直して、最後に見せる |
| 画像の差し替え | 商品写真の変更 | content.md の素材の表、カンプ、HTML | 続けて直して、最後に見せる |
| ブロックを外す | 「ご当選された方へは不要」 | blocks.md（チェックを外し、メモに理由）、カンプ、HTML | 続けて直して、最後に見せる |
| 並べ替え | 「シーンを特長の前に」 | blocks.md、カンプ、HTML | 続けて直して、最後に見せる |
| ブロックを足す | 新しい訴求、動画 | content.md、blocks.md（B18 から続きの番号）、カンプ、HTML | **先にカンプを見せて OK をもらってから** HTML を直す |
| 見た目の変更 | 色、余白、レイアウト | カンプ、HTML | **先にカンプを見せて OK をもらってから** HTML を直す |
| 商品・配送の変更 | 対象商品や配送の条件が変わる | content.md、blocks.md の商品の表、カンプ、HTML | 続けて直して、最後に見せる |

- 直した後も、blocks.md・カンプ・HTML の3つはいつもそろえておきます（ずれると、次の修正や確認で迷うため）。
- メーカーからの依頼でも、体への効果をうたう表現や、法令の表示の言い換えは、そのまま入れずに確認します。法令の表示の差し替えは、メーカーの原稿どおりに入れます。
- Claude が人に聞くのは、依頼の意味が2通りに取れる、直す場所が分からない、素材が足りない、依頼どうしがぶつかる、のどれかのときだけです。

## フォルダと記録

```
projects/{案件番号}/
├── changes.md            修正の記録（回ごとの依頼と対応）
└── revisions/
    ├── round-1/          第1回の修正
    │   ├── request/      受け取ったファイル（そのまま）
    │   └── before/       直す前の dist/（Claude が作る）
    └── round-2/
        ├── request/
        └── before/
```

### before/ の使い道

`before/` は、その回の修正を始める直前の `dist/`（HTML・CSS・画像）をまるごと写したものです。Claude が自動で作ります。

| 使い道 | 頼み方の例 |
|---|---|
| 回ごと元に戻す | 「第2回の修正を取り消して」 → `round-2/before/` を `dist/` に写し戻す |
| 一部だけ戻す | 「シーンのブロックだけ第1回の前に戻して」 → `round-1/before/` からその部分だけを戻す |
| 何を変えたかを確かめる | 「第2回で何を変えた？」 → `before/` と今の `dist/` を比べて答える。頼まれていないところを誤って変えていないかの確認にも使う |
| 公開していた版を知る | 公開後の修正なら、その回の `before/` が修正する前に公開していた版 |

1回分は画像を含めて数MB 程度です。

### changes.md の例

```markdown
## 第1回（2026-11-24、依頼元: メーカー）

| # | 依頼 | 種類 | 直したもの | 状態 |
|---|---|---|---|---|
| 1-1 | 「ご当選された方へ」は不要 | ブロックを外す | blocks.md、カンプ、HTML | 済 |

- 受け取ったもの: `revisions/round-1/request/`
- 直す前の版: `revisions/round-1/before/`
```

## 公開済みの LP を直したとき

修正した `dist/` を、もう一度公開する作業は人が行います。

- 変わった画像・`style.css` を CDN（`https://image.moratame.net/images/detail/{案件番号}/`）に上げ直す
- `<!-- 商品概要 -->` から `<!--//商品概要 -->` までを CMS に貼り直す

どのファイルが変わったかは、Claude に「上げ直すファイルを教えて」と聞けば、`before/` と比べて一覧にします。
