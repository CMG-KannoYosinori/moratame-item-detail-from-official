# 要件定義（たたき台）

モラタメ掲載商品のブランドサイトを、モラタメ個別ページ用LPへ再編集するエージェントの要件。

## 1. 目的

モラタメ掲載商品のブランドサイトを取り込み、その素材とトンマナを活かして、モラタメ個別ページ（`https://www.moratame.net/detail/tamesu.php?project_id=xxx`）の「商品概要」に入れるLPを作る。

参考にするブランドサイトの例:

- https://www.batiste.jp/
- https://nestle.jp/Starbucksathome/
- https://www.mintia.jp/product/mellome/
- https://www.ajinomoto.co.jp/cookdo/jan/

掲載先の一覧: https://www.moratame.net/detail/tamesulist.php

### 基準にするもの

- **ブランドサイトを基準にする。** 構成、トンマナ、素材はブランドサイトから組み立てる。
- 過去のモラタメ掲載ページは、掲載の形式を知るための参考にとどめる。見た目や構成をこちらに寄せる必要はない。
  - https://www.moratame.net/detail/tamesu.php?project_id=e6cf4
  - https://www.moratame.net/detail/tamesu.php?project_id=29bad
  - https://www.moratame.net/detail/tamesu.php?project_id=14156
  - https://www.moratame.net/detail/tamesu.php?project_id=18175

## 2. 処理の流れ

| # | 工程 | 入力 | 出力 | 人の確認 |
|---|---|---|---|---|
| 0 | 案件情報の聞き取り | — | 案件番号、ブランドサイトのURL、商品情報、FigmaファイルのURL | — |
| 1 | ブランドサイトのコンテンツ整理 | ブランドサイトのURL（複数可）と商品情報 | コンテンツ一覧（文言、素材、トンマナ） | — |
| 2 | ワイヤーフレーム作成 | 1の結果 | ブロック候補を並べたワイヤーフレーム（PC 640px / SP 375px） | ✅ **使うブロックと使わないブロックを選んでもらう** |
| 3 | Figmaでのデザインカンプ作成 | 2で選ばれたブロックと、1のトンマナ | PC 640px版とSP 375px版のフレーム | ✅ 承認 |
| 4 | HTMLコーディング | 確定したFigmaカンプと、テンプレート（`00000html`） | 案件番号に置き換えた `projects/{案件番号}/` 一式 | — |
| 5 | 確認 | 4の出力 | プレビュー（PC 640px / SP 375px）と確認結果 | ✅ 最終確認 |

人の確認（✅）が済むまで次の工程へ進まない。人がやるのは基本的にブロックを選ぶことだけで、選んだ後はFigma、HTMLと進められるようにする。

### 工程0: 毎回聞くこと

エージェントは作業を始めるときに、毎回次を聞く。前回の案件の値を使い回さない。

- **FigmaファイルのURL**（デザインカンプを作るファイル。毎回聞く）
- 案件番号（テンプレートの `00000` を置き換える番号。例: `15403`）
- ブランドサイトのURL（複数可）
- 商品情報（商品名、内容量、価格、お届けする商品と個数など。分かる範囲で）
- 配送の条件（通常、沖縄以外、冷凍便、冷蔵便のどれか。注意書きを選ぶのに使う）

練習用のFigmaファイル: https://www.figma.com/design/HWYyk4s3XL0ISOUK2ppFHP/brand-site-to-moratame-lp

## 3. コンテンツ整理とワイヤーフレーム

### 3.1 コンテンツ整理（工程1）

ブランドサイトの各ページから、次を一覧にする。

- ブランドサイトによっては、自動での読み取りを拒否される（HTTP 403。サントリーやアサヒ飲料などで確認）。そのときは止まって人に伝え、保存したHTMLやスクリーンショットをもらう。

- **文言:** キャッチコピー、商品の特長、使い方、原材料名、栄養成分、アレルギー、注意事項など。出典のURLも残す。
- **素材:** 写真、イラスト、ロゴ、動画（YouTubeなど）。URL、サイズ、何に使えそうかを書く。
- **トンマナ:** 基本の色、アクセントの色、書体、あしらい（角丸、線、背景の模様など）。
- **薬機法・景表法に関わりそうな表現:** 注釈付きの記載をそのまま控えておく（言い換えない）。

### 3.2 ワイヤーフレーム（工程2）

- 整理したコンテンツを、LPのブロック候補として**多めに**並べる。人が選んで減らす前提。
- 各ブロックにはIDを振る（例: `B01 KV`、`B02 商品の特長3点`）。それぞれに、元にしたブランドサイトのページと、使うテンプレート部品（7節）を書く。テンプレートに部品がないブロックは「案件専用」と書く。
- 見た目はグレーの箱と実際の文言だけの簡易なもの。色や装飾はまだ入れない。
- **形式:**
  - `wireframe.html`: PC 640pxとSP 375pxを横に並べてブラウザで見られる簡易HTML
  - `blocks.md`: ブロックIDのチェックリスト。人は使うブロックにチェックを入れる（並び替えや、文言を直す指示もここに書ける）
- 人がチェックした `blocks.md` を、工程3以降の正とする。
- `wireframe.html` は開いたときに `blocks.md` を読み込み、チェック（使わないブロックは薄く表示）、並び順、メモ（付箋）をその場で反映する。Live Server で開けば、`blocks.md` を保存するたびに自動で再読み込みされる。ファイルを直接開くと読み込めないので、そのときは最初のおすすめで表示し、その旨を画面に出す。
- インラインのJSの中には `</body>` などの閉じタグを文字どおりに書かない（`<\/body>` と書く）。Live Server が最初の `</body>` の前にスクリプトを差し込み、JSが壊れるため。

## 4. デザインカンプ（Figma）

- 作るのは、工程0で聞いたFigmaファイル。
- 工程2で選ばれたブロックだけを、選ばれた順に組む。
- **PC:** 幅640px。外枠の1pxボーダーを含むので、中身は638px。
- **SP:** 幅375px。こちらも1pxのボーダーを含むので、中身は373px。
- テンプレートの切り替え幅は640px（`width >= 640px` がPC）。SPカンプはそれより狭い幅で、中身が伸び縮みする前提で作る。
- **SPの基準は375px。** テンプレートのルール（`design-comp.mdc`）には「SPは320pxが基準」とあるが、このリポジトリでは375pxを優先する。320pxでも崩れないことはHTMLの確認（工程5）で見る。
- ブランドサイトの色、フォント、写真、あしらいを再利用する。
- **テンプレートの既存部品（7節）を優先して組む。** 部品にない見た目だけを案件専用のデザインにする。
- 素材は画像として書き出せる単位で組む（コーディング時に、画像にする部分とテキストにする部分を分けるため）。
- 商品名、内容量、価格、注意事項などのテキストは、画像にせずHTMLのテキストにする前提で設計する。
- 確定したカンプは、コーディング用に `design/{案件番号}-pc.png` と `design/{案件番号}-sp.png` として書き出す（テンプレートの決まりに合わせる）。

## 5. 成果物の形（テンプレート `item-details-template` に準拠）

テンプレート: [references/moratame/item-details-template/](../references/moratame/item-details-template/)。案件ではその中の `00000html/` だけをコピーして使い、`00000` を案件番号に一括置換する。

### 5.1 フォルダ構成

```
projects/{案件番号}/
├── wireframe/                  # 工程1・2の出力（content.md、wireframe.html、blocks.md）
├── design/                     # カンプのPNG（工程3でFigmaから書き出す）
├── dist/                       # 納品物
│   ├── {案件番号}.html
│   ├── images/
│   ├── scripts/accordion.2.js  # アコーディオンを使うときだけ
│   └── styles/style.css        # SCSSのコンパイル結果（直接編集しない）
└── src/styles/                 # SCSS（Modern BEM）
    ├── style.scss              # 入口
    ├── foundation/  layout/  blocks/
    └── pages/_project.scss     # 案件専用のスタイルはここだけに書く
```

### 5.2 HTMLの構造

`{案件番号}.html` のうち、CMSに埋め込むのは `<!-- 商品概要 -->` から `<!--//商品概要 -->` までの範囲。それより外側（`<head>` のモラタメ共通CSSやjQueryなど）はプレビュー用の枠。

```html
<!-- 商品概要 -->
<link href=".../common--set.css"> <link href=".../common--attention--201806251600.css">
<link href="./styles/style.css">               <!-- 公開時は CDN の URL に切り替える -->
<div class="p{案件番号}">
  <article class="p{案件番号}-main p{案件番号}-project">
    <!-- 制作範囲: KV、各セクション、商品ラインナップ、バナー、X投稿CTA など -->
  </article>
  <div class="pjt--common">
    include_tpl                                <!-- 「今回タメせる商品」はシステムが差し込む -->
    <!-- 送料関係の注意書き: 通常 / 沖縄以外 / 冷凍便 / 冷蔵便 から1つ選ぶ -->
  </div>
</div>
<script src="./scripts/accordion.2.js"></script>  <!-- 使うときだけ。公開時は CDN の URL に切り替える -->
<!--//商品概要 -->
```

### 5.3 外枠とレスポンシブ

- `.p{案件番号}` に `max-width: 640px`、`.p{案件番号}-main` に `border: 1px solid #ccc`（`box-sizing: border-box`）。**1pxのボーダーはHTML側で付くので、カンプの中身は638px。**
- 切り替え幅は640px。SCSSでは `@media (width >= 640px)` をセレクタの中に入れ子にして書く。
- 基本の文字サイズはSP 14px、PC 16px。基本フォントは游ゴシック系。Google Fontsの Noto Sans JP / Noto Serif JP / M PLUS Rounded 1c は読み込み済み。

### 5.4 公開時のファイルの置き場所

| 種類 | URL |
|---|---|
| CSS | `https://image.moratame.net/images/detail/{案件番号}/styles/style.css` |
| 画像 | `https://image.moratame.net/images/detail/{案件番号}/images/...` |
| JS | `https://image.moratame.net/images/detail/{案件番号}/scripts/accordion.2.js` |
| 共通CSS | `https://image.moratame.net/images/detail/common/common--set.css`、`common--attention--201806251600.css` |

### 5.5 コーディング規約

ルールの正は [references/moratame/item-details-template/.cursor/rules/](../references/moratame/item-details-template/.cursor/rules/)。エージェントは作業のたびにここを読む（`.claude/rules/` も同じ内容）。主な内容は次のとおり。


- **文字コード:** ファイルは UTF-8 で保存し、`<meta charset>` は書かない。埋め込み先は Shift_JIS のCMS（モラタメ）と UTF-8 のCMS（シェアフル）の両方。
- **記号:** ®、×、〜、① などは数値文字参照（`&#174;` など）で書く。`&reg;` のような名前付きの実体参照は使わない。CSSの `content` ではUnicodeエスケープを使う。
- **命名:** クラス名には `p{案件番号}-` を付けた Modern BEM。孫要素（`__a__b`）は作らない。ある部品を親の部品から直接上書きしない。
- **案件専用のCSS:** `pages/_project.scss` の `.p{案件番号}-project` とその `__` 要素だけに書く。共通部品（`blocks/`）を案件のために書き換えない。
- **リンク:** jQuery Mobile 対策で `data-role="none"` を付ける（テンプレートの例に合わせる）。
- **カンプに忠実に:** カンプにない要素や文言は足さない。
- **コミット:** gitmojiを付け、意味ごとに分ける。

## 6. 品質・制約

- 画像は中身の幅638pxの2倍、**1276px** を基準に書き出して圧縮する（テンプレートのKVが 1276&#215;1276）。webp を使ってよいかは要確認。
- 画像には alt を入れ、`width` と `height` も書く。
- ブランドサイトの素材は**クライアントから使用許諾を得ている前提**とする。勝手に流用しないための確認項目を工程に入れる。
- 薬機法や景表法に関わる表現は、ブランドサイトの記載を勝手に言い換えない。
- ブランド独自のWebフォントは、ライセンスと読み込み方法を確認してから使う。確認できないものは近い書体（読み込み済みのGoogle Fontsなど）で代用する。

## 10. 実装の方針

チームメンバーに使ってもらうまでの段階と準備は [team-rollout.md](./team-rollout.md) にまとめた。

### 10.1 実行環境: Claude Code のスキル

エージェントは、Claude Code のプロジェクトスキル（`.claude/skills/`）として作る。

理由:
- Figmaとの接続（Figma MCP）が Claude Code ですでに使える。
- 人の確認（ブロックを選ぶ、カンプを承認する）を、会話の中でそのまま挟める。
- サーバーなどを用意しなくてよい。

自動で何件も回したくなったら、そのときに Agent SDK へ移す。

スキルの構成（案）:

| スキル | 担当する工程 |
|---|---|
| `moratame-lp` | 全体の進行役。工程0で聞き取り、各工程のスキルを順に呼び、人の確認で止まる |
| `brand-content` | 工程1: コンテンツ整理 |
| `lp-wireframe` | 工程2: ワイヤーフレームと `blocks.md` |
| `figma-comp` | 工程3: Figmaでのデザインカンプ作成 |
| `moratame-html` | 工程4・5: テンプレートからのコーディングと確認 |

案件ごとの作業フォルダは `projects/{案件番号}/` に置く。中身は5.1節の構成。

### 10.2 テンプレート: サブモジュール

`references/moratame/item-details-template/` は、Gitのサブモジュールとして登録する。テンプレートが更新されたら、`git submodule update --remote` で取り込める。

- このリポジトリを新しく clone するときは `git clone --recursive` を使う（または clone の後に `git submodule update --init`）。
- テンプレートの中身はこのリポジトリでは編集しない。直すときはテンプレートのリポジトリ側で直す。
- 案件を始めるときは、テンプレートの `00000html/` の中身（`dist/` と `src/`）を `projects/{案件番号}/` にコピーして使う。
- 詳しい手順は [submodule.md](./submodule.md) にまとめた。
