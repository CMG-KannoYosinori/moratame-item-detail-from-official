# 要件定義（たたき台）

モラタメ掲載商品のブランドサイトを、モラタメ個別ページ用LPへ再編集するエージェントの要件。

## 1. 目的

モラタメ掲載商品のブランドサイトを取り込み、その素材とトンマナを活かして、モラタメ個別ページ（`https://www.moratame.net/detail/tamesu.php?project_id=xxx`）の「商品概要」に入れるLPを作る。

参考にするブランドサイトの例:

- https://www.batiste.jp/
- https://nestle.jp/Starbucksathome/
- https://www.mintia.jp/product/mellome/
- https://www.ajinomoto.co.jp/cookdo/jan/

掲載先の一覧: https://www.moratame.net/detail/tamesulist.php

### 基準にするもの

- **ブランドサイトを基準にする。** 構成、トンマナ、素材はブランドサイトから組み立てる。
- 過去のモラタメ掲載ページは、掲載の形式を知るための参考にとどめる。見た目や構成をこちらに寄せる必要はない。
  - https://www.moratame.net/detail/tamesu.php?project_id=e6cf4
  - https://www.moratame.net/detail/tamesu.php?project_id=29bad
  - https://www.moratame.net/detail/tamesu.php?project_id=14156
  - https://www.moratame.net/detail/tamesu.php?project_id=18175

## 2. 処理の流れ

| # | 工程 | 入力 | 出力 | 人の確認 |
|---|---|---|---|---|
| 0 | 案件情報の聞き取り | — | 案件番号、ブランドサイトのURL、商品情報、FigmaファイルのURL | — |
| 1 | ブランドサイトのコンテンツ整理 | ブランドサイトのURL（複数可）と商品情報 | コンテンツ一覧（文言、素材、トンマナ） | — |
| 2 | ワイヤーフレーム作成 | 1の結果 | ブロック候補を並べたワイヤーフレーム（PC 640px / SP 375px） | ✅ **使うブロックと使わないブロックを選んでもらう** |
| 3 | Figmaでのデザインカンプ作成 | 2で選ばれたブロックと、1のトンマナ | PC 640px版とSP 375px版のフレーム | ✅ 承認 |
| 4 | HTMLコーディング | 確定したFigmaカンプと、テンプレート（`00000html`） | 案件番号に置き換えた `projects/{案件番号}/` 一式 | — |
| 5 | 確認 | 4の出力 | プレビュー（PC 640px / SP 375px）と確認結果 | ✅ 最終確認 |
| 6 | 修正対応（何回でも） | メーカーからの戻しや社内の指摘（文章、メール、赤字の PDF・画像） | 直した blocks.md・カンプ・HTML と、修正の記録 `changes.md` | ✅ 修正の確認 |

人の確認（✅）が済むまで次の工程へ進まない。人がやるのは基本的にブロックを選ぶことだけで、選んだ後はFigma、HTMLと進められるようにする。

### 工程6: 修正対応

HTML を作った後（公開後も含む）には、メーカーからの戻しなどで修正が何度も入る前提にする。スキルは `lp-revise`、人向けの説明は [revision-flow.md](./revision-flow.md)。

- 工程を最初からやり直さない。依頼を1件ずつに分け、種類（文言・数値、画像の差し替え、ブロックを外す、並べ替え、ブロックを足す、見た目の変更、商品・配送の変更）ごとに、影響するもの（content.md・blocks.md・カンプ・HTML）だけを直す。
- 直した後も、blocks.md・カンプ・HTML の3つをそろえておく。
- 見た目が新しくなる直し（ブロックを足す、見た目の変更）は、先にカンプを直して確認をもらってから HTML を直す。それ以外は続けて直し、最後にまとめて確認してもらう。
- 回ごとに `projects/{案件番号}/revisions/round-{N}/` を作り、受け取ったファイルを `request/` に、直す前の `dist/` を `before/` に残す。`before/` は、元に戻す、変えたところを確かめる、公開していた版を知るのに使う。
- 依頼と対応は `projects/{案件番号}/changes.md` に第N回ごとに記録する。
- メーカーからの依頼でも、体への働きをうたう表現や法令の表示の言い換えは、そのまま入れずに人に確認する。

### 工程0: 毎回聞くこと

エージェントは作業を始めるときに、毎回次を聞く。前回の案件の値を使い回さない。

- **FigmaファイルのURL**（デザインカンプを作るファイル。毎回聞く）
- 案件番号（テンプレートの `00000` を置き換える番号。例: `15403`）
- ブランドサイトのURL（複数可）
- **対象商品**（モラタメで今回試せる商品）と個数。分かる範囲で。まだ決まっていなければ、工程2で商品一覧から選ぶ
- 商品情報（内容量、価格など。分かる範囲で）
- 配送の条件（通常、沖縄以外、冷凍便、冷蔵便のどれか。注意書きを選ぶのに使う）

練習用のFigmaファイル: https://www.figma.com/design/HWYyk4s3XL0ISOUK2ppFHP/brand-site-to-moratame-lp

## 3. コンテンツ整理とワイヤーフレーム

### 3.1 コンテンツ整理（工程1）

ブランドサイトの各ページから、次を一覧にする。

- ブランドサイトによっては、自動での読み取りを拒否される（HTTP 403。サントリーやアサヒ飲料などで確認）。そのときは止まって人に伝え、保存したHTMLやスクリーンショットをもらう。

- **文言:** キャッチコピー、商品の特長、使い方、原材料名、栄養成分、アレルギー、注意事項など。出典のURLも残す。
- **素材:** 写真、イラスト、ロゴ、動画（YouTubeなど）。URL、サイズ、何に使えそうかを書く。
- **トンマナ:** 基本の色、アクセントの色、書体、あしらい（角丸、線、背景の模様など）。
- **薬機法・景表法に関わりそうな表現:** 注釈付きの記載をそのまま控えておく（言い換えない）。
- **商品一覧:** ブランドサイトに載っている商品を、対象かどうかに関係なくすべて挙げる。IDを振り（`P1`、`P2`…）、内容量・スペック・画像・商品ページのURLを書く。

### 3.2 ワイヤーフレーム（工程2）

- 整理したコンテンツを、LPのブロック候補として**多めに**並べる。人が選んで減らす前提。
- 各ブロックにはIDを振る（例: `B01 KV`、`B02 商品の特長3点`）。それぞれに、元にしたブランドサイトのページと、使うテンプレート部品（7節）を書く。テンプレートに部品がないブロックは「案件専用」と書く。
- 各ブロックには種類を付ける。
  - **必須:** KV、商品ラインナップ（商品の説明・スペック・アレルギーなど）、法令で求められる表示（栄養機能食品の表示など）
  - **おすすめ:** ブランドサイトの主要な訴求、ブランドサイトへのバナー、X投稿のお願いなど。最初からチェックを付けておく
  - **任意:** あってもよいもの。今回お届けする商品（`-delivering-items`）もここ。最初はチェックを外しておく
- **商品ラインナップの商品:** `blocks.md` の「商品」の表で、工程1の商品一覧の各商品に区分を付ける。
  - **対象:** モラタメで今回試せる商品。商品名の上に「今回試せる商品」のラベルを付け、ラインナップの先頭に並べる。1つ以上必要（すべての商品が対象でもよい）
  - **紹介:** 紹介だけする商品。ラベルは付けない
  - **載せない:** ラインナップに出さない
  - 最初の区分は、工程0で聞いた対象商品を「対象」にし、ほかは関係の近いものを「紹介」、それ以外を「載せない」にしておく。
- 見た目はグレーの箱と実際の文言だけの簡易なもの。色や装飾はまだ入れない。
- **形式:**
  - `wireframe.html`: PC 640pxとSP 375pxを横に並べてブラウザで見られる簡易HTML
  - `blocks.md`: ブロックIDのチェックリスト。使うかどうか、並び順、メモ（文言を直す指示など）を持つ
- 人がチェックした `blocks.md` を、工程3以降の正とする。
- **保存の後の見直し（対話）:** 人が保存したら、エージェントが `blocks.md` を読み、抜け漏れ・重複・表現の注意点を短く挙げる。人は追加や修正を自然な言葉で頼める（例:「B05のPoint3を短く」「コラムの○○をブロックにして」）。エージェントは `blocks.md`・`wireframe.html`・`content.md` を直し、人はページを再読み込みして確かめる。新しいブロックは続きのID（`B18`…）で足す。人が「これで進めて」と言ったら工程3に進む。
  - エージェントが `blocks.md` を直す前に、画面で選んだ内容を保存しておいてもらう（保存していない変更は、再読み込みで消えるため）。
- **選び方:** `python3 tools/wireframe-server.py` を起動し、表示されたURLで `wireframe.html` を開く。各ブロックのタグにあるチェックボックス・↑↓・メモで選び、「blocks.md に保存」（⌘+S）を押すと `blocks.md` に書き戻る。
  - 商品ラインナップの各商品カードの右上で、区分（対象 / 紹介のみ / 載せない）を選べる。
  - 書き戻すのは、ブロックの表のチェック・並び順・メモと、商品の表の区分だけ。変えていない行や、表以外の部分はそのまま残す。
  - 必須のブロックを外すときは、メモに理由がないと保存できない。対象の商品が1つもないときも保存できない。
  - ページを開いた後に `blocks.md` がほかで書き換えられていたら、上書きせずに保存を止める。
  - サーバーは自分のPC（127.0.0.1）からだけ見られ、書き込めるのは既存の `projects/*/wireframe/blocks.md` だけ。
- Live Server など、保存できないサーバーで開いたときは「選んだ結果をコピー」を出す。ファイルを直接開いたときは `blocks.md` を読めないので、最初のおすすめで表示し、その旨を画面に出す。
- インラインのJSの中には `</body>` などの閉じタグを文字どおりに書かない（`<\/body>` と書く）。Live Server が最初の `</body>` の前にスクリプトを差し込み、JSが壊れるため。

## 4. デザインカンプ（Figma）

- 作るのは、工程0で聞いたFigmaファイル。
- 工程2で選ばれたブロックだけを、選ばれた順に組む。
- **PC:** 幅640px。外枠の1pxボーダーを含むので、中身は638px。
- **SP:** 幅375px。こちらも1pxのボーダーを含むので、中身は373px。
- テンプレートの切り替え幅は640px（`width >= 640px` がPC）。SPカンプはそれより狭い幅で、中身が伸び縮みする前提で作る。
- **SPの基準は375px。** テンプレートのルール（`design-comp.mdc`）には「SPは320pxが基準」とあるが、このリポジトリでは375pxを優先する。320pxでも崩れないことはHTMLの確認（工程5）で見る。
- ブランドサイトの色、フォント、写真、あしらいを再利用する。
- **カンプが HTML の見本になる。** テンプレートの既存部品（7節）の形を参考にしてよいが、見た目はブランドに合わせてよい。HTML ではカンプどおりに組み、部品の見た目と違うところは案件専用の要素で組む。
- **X投稿のお願い（`-cta-x`、「ご当選された方へ」）だけは、テンプレートの部品の見た目と文言のまま使う。**
- 素材は画像として書き出せる単位で組む（コーディング時に、画像にする部分とテキストにする部分を分けるため）。
- 商品名、内容量、価格、注意事項などのテキストは、画像にせずHTMLのテキストにする前提で設計する。
- 確定したカンプは、コーディング用に `design/{案件番号}-pc.png` と `design/{案件番号}-sp.png` として書き出す（テンプレートの決まりに合わせる）。

## 5. 成果物の形（テンプレート `item-details-template` に準拠）

テンプレート: [template/00000html/dist/](../template/00000html/dist/)（[item-details-template](https://github.com/CMG-KannoYosinori/item-details-template) から写したもの。取り込み元は [template/SOURCE.md](../template/SOURCE.md)）。案件ではこの `dist/` を `projects/{案件番号}/dist/` にコピーして使い、`00000` を案件番号に一括置換する。**SCSS は使わず、CSS だけで運用する。**

### 5.1 フォルダ構成

```
projects/{案件番号}/
├── wireframe/                  # 工程1・2の出力（content.md、wireframe.html、blocks.md）
├── design/                     # カンプのPNG（工程3でFigmaから書き出す）
├── dist/                       # 納品物
│   ├── {案件番号}.html
│   ├── images/
│   ├── scripts/accordion.2.js  # アコーディオンを使うときだけ
│   └── styles/style.css        # テンプレートの CSS ＋ 最後に案件専用の CSS
```

`style.css` は、テンプレートのコンパイル済み CSS をそのまま写したもの。案件のスタイルは、ファイルの最後に「案件専用ここから」の区切りのコメントを置き、その下に書く（区切りより上は編集しない）。公開時に CDN へ上げるのも、この1ファイル。

### 5.2 HTMLの構造

`{案件番号}.html` のうち、CMSに埋め込むのは `<!-- 商品概要 -->` から `<!--//商品概要 -->` までの範囲。それより外側（`<head>` のモラタメ共通CSSやjQueryなど）はプレビュー用の枠。

```html
<!-- 商品概要 -->
<link href=".../common--set.css"> <link href=".../common--attention--201806251600.css">
<link href="./styles/style.css">               <!-- 公開時は CDN の URL に切り替える -->
<div class="p{案件番号}">
  <article class="p{案件番号}-main p{案件番号}-project">
    <!-- 制作範囲: KV、各セクション、商品ラインナップ、バナー、X投稿CTA など -->
  </article>
  <div class="pjt--common">
    include_tpl                                <!-- 「今回タメせる商品」はシステムが差し込む -->
    <!-- 送料関係の注意書き: 通常 / 沖縄以外 / 冷凍便 / 冷蔵便 から1つ選ぶ -->
  </div>
</div>
<script src="./scripts/accordion.2.js"></script>  <!-- 使うときだけ。公開時は CDN の URL に切り替える -->
<!--//商品概要 -->
```

### 5.3 外枠とレスポンシブ

- `.p{案件番号}` に `max-width: 640px`、`.p{案件番号}-main` に `border: 1px solid #ccc`（`box-sizing: border-box`）。**1pxのボーダーはHTML側で付くので、カンプの中身は638px。**
- 切り替え幅は640px。SP を基本に書き、PC は同じセレクタのすぐ下に `@media (width >= 640px)` で書く（入れ子は使わない）。
- 基本の文字サイズはSP 14px、PC 16px。基本フォントは游ゴシック系。Google Fontsの Noto Sans JP / Noto Serif JP / M PLUS Rounded 1c は読み込み済み。

### 5.4 公開時のファイルの置き場所

| 種類 | URL |
|---|---|
| CSS | `https://image.moratame.net/images/detail/{案件番号}/styles/style.css` |
| 画像 | `https://image.moratame.net/images/detail/{案件番号}/images/...` |
| JS | `https://image.moratame.net/images/detail/{案件番号}/scripts/accordion.2.js` |
| 共通CSS | `https://image.moratame.net/images/detail/common/common--set.css`、`common--attention--201806251600.css` |

### 5.5 コーディング規約

ルールは [.claude/rules/](../.claude/rules/)（`projects/` の HTML・CSS を扱うときに自動で読み込まれる）。item-details-template のルールをもとに、CSS で運用する形・SP 375px に書き直した。主な内容は次のとおり。


- **文字コード:** ファイルは UTF-8 で保存し、`<meta charset>` は書かない。埋め込み先は Shift_JIS のCMS（モラタメ）と UTF-8 のCMS（シェアフル）の両方。
- **記号:** ®、×、〜、① などは数値文字参照（`&#174;` など）で書く。`&reg;` のような名前付きの実体参照は使わない。CSSの `content` ではUnicodeエスケープを使う。
- **命名:** クラス名には `p{案件番号}-` を付けた Modern BEM。孫要素（`__a__b`）は作らない。ある部品を親の部品から直接上書きしない。
- **案件専用のCSS:** `style.css` の最後の区切りより下に、`.p{案件番号}-project` とその `__` 要素だけを書く。テンプレートの部品の CSS を案件のために書き換えない。
- **リンク:** jQuery Mobile 対策で `data-role="none"` を付ける（テンプレートの例に合わせる）。
- **カンプに忠実に:** カンプにない要素や文言は足さない。
- **コミット:** git で管理しているとき（管理者）は、gitmojiを付け、意味ごとに分ける。

## 6. 品質・制約

- 画像は中身の幅638pxの2倍、**1276px** を基準に書き出して圧縮する（テンプレートのKVが 1276&#215;1276）。webp を使ってよいかは要確認。
- 画像には alt を入れ、`width` と `height` も書く。
- ブランドサイトの素材は**クライアントから使用許諾を得ている前提**とする。勝手に流用しないための確認項目を工程に入れる。
- 薬機法や景表法に関わる表現は、ブランドサイトの記載を勝手に言い換えない。
- ブランド独自のWebフォントは、ライセンスと読み込み方法を確認してから使う。確認できないものは近い書体（読み込み済みのGoogle Fontsなど）で代用する。

## 7. テンプレートの既存部品

工程2（ワイヤーフレーム）、工程3（デザイン）、工程4（コーディング）は、まずこれらの部品を組み合わせる。

| 部品 | 用途 |
|---|---|
| `-mv` | KV（メインビジュアル。1276&#215;1276の画像） |
| `-delivering-items` | 今回お届けする商品（画像と個数） |
| `-section` / `-container` / `-box` / `-heading` | セクション、余白、白いボックス、見出し |
| `-line-up` | 商品ラインナップのカード（商品名、画像、説明、スペック、アレルギー、アコーディオン、ボタン）。対象商品には商品名の上に「今回試せる商品」のラベルを付ける |
| `-balloon` | 下向きの三角が付いたキャッチコピー |
| `-item-label` | 医薬部外品などの区分ラベル |
| `-item-spec`（`--horizontal`） | 内容量・価格など（`dl`） |
| `-allergy` | アレルギー情報 |
| `-accordion-details` | 開閉するアコーディオン（`details` と JS） |
| `-youtube` | YouTubeの埋め込み |
| `-banner` | ブランドサイトへのバナー |
| `-cta-x` | X（旧Twitter）への投稿を促すCTA（ハッシュタグとボタン） |
| `-button` | 共通ボタン |
| レイアウト用 | 余白（`-mt-4` など）、表示切り替え（`pc:p{ID}-hidden`）、書体、ぶら下げインデント、上付きの注釈 |

## 10. 実装の方針

チームメンバーに使ってもらうまでの段階と準備は [team-rollout.md](./team-rollout.md) にまとめた。

### 10.1 実行環境: Claude Code のスキル

エージェントは、Claude Code のプロジェクトスキル（`.claude/skills/`）として作る。**作成済み**（2026-11-24）。工程4・5の `moratame-html` は、まだ実案件で通していないので、1件目で見直す。人向けの使い方は [manual.md](./manual.md)。

理由:
- Figmaとの接続（Figma MCP）が Claude Code ですでに使える。
- 人の確認（ブロックを選ぶ、カンプを承認する）を、会話の中でそのまま挟める。
- サーバーなどを用意しなくてよい。

自動で何件も回したくなったら、そのときに Agent SDK へ移す。

スキルの構成:

| スキル | 担当する工程 |
|---|---|
| `moratame-lp` | 全体の進行役。工程0で聞き取り、各工程のスキルを順に呼び、人の確認で止まる |
| `brand-content` | 工程1: コンテンツ整理 |
| `lp-wireframe` | 工程2: ワイヤーフレームと `blocks.md` |
| `figma-comp` | 工程3: Figmaでのデザインカンプ作成 |
| `moratame-html` | 工程4・5: テンプレートからのコーディングと確認 |

案件ごとの作業フォルダは `projects/{案件番号}/` に置く。中身は5.1節の構成。

共通の道具（`tools/`）:

| ファイル | 役割 |
|---|---|
| `tools/wireframe/template.html`・`blocks.template.md` | 新しい案件のワイヤーフレームと `blocks.md` のひな形 |
| `tools/wireframe/wireframe.js`・`wireframe.css`・`frame.css` | ワイヤーフレームの見た目と動き（全案件で共通） |
| `tools/wireframe-server.py` | ワイヤーフレームと HTML のプレビュー（`charset=utf-8` を付けて返す）、`blocks.md` への保存 |
| `tools/preview.html` | HTML を決めた幅（375px・320px など）の iframe で表示する。SP の幅のスクリーンショットに使う |
| `tools/figma-upload.sh` | 素材を Figma に上げる |
| `.claude/skills/figma-comp/helpers.js` | Figma でカンプを組むときの共通の関数 |

### 10.2 テンプレート: このリポジトリに写す

テンプレートは [item-details-template](https://github.com/CMG-KannoYosinori/item-details-template) から、案件で使う部分（`00000html/dist/` と README）だけを `template/` に写して持つ。最初はサブモジュールにしていたが、スタッフに zip で配る運用にしたため変えた。

- `template/` はこのリポジトリでは編集しない。直すときは item-details-template で直し、管理者が `tools/update-template.sh` で取り込み直す（取り込み元のコミットは [template/SOURCE.md](../template/SOURCE.md) に記録する）。
- ルールは `.claude/rules/` に、CSS で運用する形に書き直して持つ。取り込み元のルールが変わったら、管理者が差分を見て手で反映する。
- 案件を始めるときは、`template/00000html/dist/` を `projects/{案件番号}/dist/` にコピーして使う。

### 10.3 配り方: zip と Google Drive

スタッフには git を使わせない。管理者（このリポジトリを git で管理する人）が zip を作り、Google Drive の `共有ドライブ/design2/MOD_design/モラタメ商品概要LP_AIエージェント制作/01_エージェント最新版/` に手動で置く。案件を始めるたびに、最新の zip を `02_案件ごとの作業フォルダ/` に展開してフォルダ名を `案件番号_商品名`（例: `99902_牛乳石鹸AKA`）に変え、Claude のアプリで開いて使う（1フォルダ1案件、1案件1人）。管理者の実際の案件も同じように作る。

- zip は `tools/make-dist.sh` で作る。管理者の案件（`projects/` の中身）、`.git`、管理者向けの文書・ルールは入れない。版の番号（`VERSION`）を入れる。
- 案件の作業は、その案件フォルダの `projects/` に残る（進み具合の記録 `projects/progress.md` も含む）。案件の途中で新しい版が出ても、始めたときの版のまま続ける。
- フィードバックは各案件フォルダの `feedback/` に残り、管理者が `tools/collect-feedback.sh` で集める（[feedback-flow.md](./feedback-flow.md)）。
- 手順は、スタッフ向けが [manual.md](./manual.md)、管理者向けが [admin.md](./admin.md)。
