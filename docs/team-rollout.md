# チームで使うまでのプラン

最終的には、git・HTML・Figma に慣れていないチームメンバーも、このエージェントでLPを作れるようにする。この文書はそこまでのプランで、進めながら変えていく。

- **いまの段階:** 段階1（作成者が1人で手順を固める）。段階2のスキルとマニュアルは前倒しで作成済み
- **最終更新:** 2026-11-24

## 1. 目指す使い方

メンバーは、管理者が zip で配るフォルダを Claude アプリの **Code** で開き、入口のスキルを1つ呼ぶだけにする。質問に答え、見せられた画面を確認すれば、LPができる。git やファイルの編集には触れさせない。作業はメンバーの PC の中だけで行う。

| 工程 | メンバーがすること | エージェントがすること |
|---|---|---|
| 開始 | `/moratame-lp` と打つ | 案件番号、ブランドサイトのURL、FigmaのURL、対象商品（分かれば）、商品情報、配送の条件を、選択肢つきの質問で聞く |
| 内容の整理（工程1） | なし | ブランドサイトを読んで整理する。読めないサイトは、保存したHTMLやスクリーンショットをもらう |
| ブロックの選択（工程2） | ブラウザで開かれたワイヤーフレームで、各ブロックのチェックボックスを付け外しし、商品ごとに「対象 / 紹介のみ / 載せない」を選び、必要ならメモを書いて「保存」を押す | プレビュー用の小さなサーバーを起動しておき、保存された内容を `blocks.md` に書き込む |
| 見直し（工程2） | エージェントが挙げた抜け漏れや注意点を見て、追加・修正を言葉で頼む。ページを再読み込みして確かめ、よければ「これで進めて」と伝える | `blocks.md` を読んで抜け漏れ・重複・表現の注意点を挙げる。頼まれた内容でブロックを足したり直したりする |
| デザイン（工程3） | Figmaで、直してほしい場所に **Figmaのコメント** を書く。終わったら「確認した」と伝える | コメントを読んで直し、コメントに返信する |
| HTML（工程4・5） | ブラウザで開かれたプレビューを、PC幅とスマホ幅で見る。気になる点を言葉で伝える | 直してチェックし、納品物をまとめる |
| 案件の終わり | `projects/{案件番号}/` を共有の場所に置く | 公開の前に人がやることをまとめる |

### いまのやり方との違い

| 項目 | いま（段階1） | 目指す形 |
|---|---|---|
| ブロックの選択 | `blocks.md` を直接編集する | ワイヤーフレームの画面上で選んで保存する |
| デザインの修正指示 | 会話で伝える | Figmaのコメント |
| プレビュー | VS Code の Live Server | エージェントがサーバーを起動してブラウザを開く |
| git | 作成者が `commit` と指示する | メンバーは使わない（管理者だけが git で管理する） |
| 配り方 | — | 管理者が zip を作って配る（`tools/make-dist.sh`）。新しい版はメンバーが `projects` を移して入れ替える |
| 実行する場所 | VS Code の Claude Code | Claude アプリの Code |

## 2. 役割分担

| 担当 | すること |
|---|---|
| 作成者（管理者） | このリポジトリを git で管理する。テンプレートの取り込み直し、スキル・ルール・マニュアルの改善、zip を作って配る、メンバーの困りごとを集める（[admin.md](./admin.md)） |
| メンバー | 上の「メンバーがすること」だけ |

メンバーの作業はメンバーの PC の中だけにある。案件が終わったら、`projects/{案件番号}/` を共有の場所に置いてもらう。

## 3. 人が判断するところ

エージェントに任せきりにしないところ。

- **表現の確認:** 薬機法・景品表示法に関わる表現は、最後に人が確認する。エージェントのチェックは補助。
- **素材の使用許可:** ブランドサイトの画像を使ってよいかは、クライアントに確認する。
- **CMSへの入稿とCDNへのアップロード:** 誤公開を防ぐため、人がやる。

## 4. 段階

### 段階1: 作成者が1人で手順を固める（いま）

- VS Code の Claude Code で、練習用の3件を順に作る。
  - サポートミート（99901）
  - 牛乳石鹸 AKA
  - キリン グッドエール
- 進めながら、[requirements.md](./requirements.md) の工程や決まりを直す。

### 段階2: スキルにする

- 固まった手順を Claude Code のスキルにする（入口の `moratame-lp` と、工程ごとのスキル。[requirements.md の 10.1](./requirements.md) を参照）。
- スキルは、質問画面を使い、メンバーにファイルを編集させない作りにする。
- 下の「5. 用意が必要なこと」を済ませる。

### 段階3: メンバー1人に試してもらう

- 4件目を、メンバー1人に作ってもらう。
- つまずいたところを、スキルや手順書に反映する。

## 5. 用意が必要なこと

| 項目 | 内容 | 状態 |
|---|---|---|
| スキル | `moratame-lp` と工程ごとのスキル | 済（`.claude/skills/`。工程4・5の `moratame-html` は実案件で未確認） |
| 許可の設定 | 安全な操作（ファイルの読み書き、プレビュー用サーバー、curl での取得など）を `.claude/settings.json` で許可しておき、確認のダイアログを減らす | 未着手 |
| ワイヤーフレームで選んで保存 | 各ブロックにチェックボックスとメモ欄を付け、「保存」で `blocks.md` に書き込めるようにする。ブラウザだけではファイルに書き込めないので、表示と保存をする小さなサーバー（エージェントが起動する）を用意する。Live Server も不要になる | 済（`tools/wireframe-server.py`。99901で動作確認済み。今後の案件のワイヤーフレームにも同じ仕組みを入れる） |
| テンプレートの持ち方 | サブモジュールをやめ、必要な部分を `template/` に写す。SCSS をやめ CSS だけで運用する | 済（`template/SOURCE.md`、`tools/update-template.sh`） |
| 配る zip | 管理者の案件・`.git`・管理者向けの文書を外した zip を作る | 済（`tools/make-dist.sh`） |
| メンバーのPC | Mac・Windows。Claude アプリ、Figma のアカウントと connector の接続、Google Drive for desktop、Python（Windows は python.org から）、Windows は Git for Windows。Chrome か Edge | 未着手（必要なものは [admin.md](./admin.md) と [manual.md](./manual.md) に書いた）。**Windows では実機で未確認** |
| 共有の場所 | Google Drive の `共有ドライブ/design2/MOD_design/モラタメ商品概要LP_AIエージェント制作`。`01_エージェント最新版/` に最新の zip、`02_案件ごとの作業フォルダ/` に案件ごとの作業フォルダ（`案件番号_商品名`） | 済（フォルダ作成済み） |
| 手順書 | メンバー向けに1枚。スクリーンショット中心の「はじめてガイド」 | 文章版を作成（[manual.md](./manual.md)）。スクリーンショットはまだ |

## 6. あとで考えること

- ブラウザ版の Claude Code（claude.ai/code）でも使えるようにするか。そのためには、メンバーの GitHub 利用と、GitHub Pages などでのプレビューが必要になる（zip の運用とは別の形になる）。
- 案件番号が決まる前に作り始めるときの、仮の番号の付け方。
