# フィードバックの流れ

このツール（Claude のスキル、マニュアル、テンプレート）は、使っている人のフィードバックで良くしていきます。管理者もスタッフも、配った版を実際の案件で使い、気づいたことをここに書いた流れで集めます。

## 全体の流れ

```
使う人（配った作業フォルダ）                 管理者（このツールのリポジトリ）
  使っていて困った・気づいた
  ↓ ①「フィードバック: 〇〇」と Claude に言う
  feedback/ にメモが1件できる
  ↓ ② 案件フォルダ（Drive）に残る   →  collect-feedback.sh で feedback/inbox/ に集める
                                       ↓ ③ Claude に「フィードバックを整理して」
                                       一覧と対応案を見て、直すものを決める
                                       ↓ ④ スキル・マニュアルなどを直す
                                       ↓ ⑤ docs/feedback-log.md に記録し、メモを feedback/done/ へ
                                       ↓ commit（配る zip が自動で作り直される）
  ⑥ 新しい版を受け取る            ←  新しい版を配り、変わったことを知らせる
```

## 使う人がすること

作業中に困ったこと、分かりにくかったこと、こうしてほしいことがあれば、Claude にそのまま言います。

```
フィードバック: ワイヤーフレームの保存ボタンがどこにあるか分からなかった
```

- Claude が `feedback/日付-時刻-題名.md` にメモを1件作ります。使っている版、案件と工程、会話から分かる状況は Claude が書き足すので、細かく説明しなくてかまいません。
- 「フィードバック:」と言わなくても、ツールの問題で作業が止まったときは、Claude が「フィードバックとして残しましょうか」と聞きます。
- 案件の中身の直し（LP の文言など）は、フィードバックではありません。いつもどおり作業として頼んでください。
- パスワードや個人の連絡先は書かないでください。クライアント名や商品名が入ることはあるので、メモは社内の共有の場所だけで扱います。

### どんなことを書けばよいか

| 種類 | 例 |
|---|---|
| 困って止まった | 「Figma が使えないと言われて進めなかった」 |
| 不具合 | 「保存したのにワイヤーフレームに反映されない」 |
| 不便・分かりにくい | 「マニュアルのこの手順が分かりにくい」「同じ質問を毎回された」 |
| 改善の提案 | 「ワイヤーフレームで画像も差し替えられるとよい」 |

小さなことでもかまいません。

## 集め方

- 作業フォルダ（Google Drive の `02_案件ごとの作業フォルダ/` の中）の `feedback/` に残るので、使う人が送る作業はありません。
- 管理者が `tools/collect-feedback.sh` で、全部の案件フォルダから集めます。

## 管理者がすること

1. `bash tools/collect-feedback.sh "<Google Drive の 案件 フォルダ>"` で、各案件フォルダのメモを、このリポジトリの `feedback/inbox/` に集める（集め済みのものは飛ばす）。
2. Claude に「フィードバックを整理して」と頼む（スキル `feedback-triage`）。
   - Claude がメモを読み、同じ原因のものをまとめ、原因（スキル・ルール・マニュアル・テンプレートなど）と対応案（直す・マニュアルで説明する・見送る）を一覧にします。古い版で起きて、今の版で直っているものは「対応済み」にします。
3. 一覧を見て、どれを直すかを決める（「全部おすすめどおりで」でもよい）。
4. Claude が直し、[feedback-log.md](feedback-log.md) に記録して、処理したメモを `feedback/done/` に移す。
5. `commit` する（配る zip が自動で作り直される）。
6. 新しい版を配り、変わったことを知らせる（Claude が知らせる文の案を作ります）。

## 記録

| ファイル | 中身 |
|---|---|
| 作業フォルダの `feedback/` | 使う人が残したメモ（1件1ファイル） |
| リポジトリの `feedback/inbox/` | 集めて、まだ整理していないメモ |
| リポジトリの `feedback/done/` | 整理が済んだメモ（見送ったものも含む） |
| リポジトリの `docs/feedback-log.md` | 受け取った日、要点、対応、反映した版の一覧 |

管理者向けの文書（`feedback-log.md`）と整理のスキル（`feedback-triage`）は、配る zip には入りません。
